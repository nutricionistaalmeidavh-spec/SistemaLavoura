# Sistema Lavoura — UI Productization Phase 4–10

## Goal
Replace every remaining technical JSON interaction with commercial, human-oriented workspaces while preserving the existing `presentation.js` contract, P0/P1/P2 behavior, IoT-ready code, local-first operation and zero mandatory software cost.

## Scope

### UI-4 — Talhões
- Dedicated fields workspace with search, KPI summary, table, create/edit form, delete confirmation and attachments.
- Use existing `fields.save`, `fields.remove`, `fields.uploadFile` and `fields.removeFile` actions.

### UI-5 — No JSON anywhere
- Remove the `ActionPanel` raw JSON editor from the product UI.
- Represent every action through explicit local UI contracts and structured forms.
- Include Settings, Inputs and Harvest so no screen falls back to developer-facing JSON.

### UI-6 — Dialog system
- Add accessible modal/dialog primitives for create/edit/confirm/destructive flows.
- Provide consistent pending/error/close behavior.

### UI-7 — Safras and Operações
- Dedicated seasons workspace with structured create/edit form.
- Operations workspace grouped by status with schedule/start/complete/cancel flows, planning information and minimal checklist controls.

### UI-8 — Estoque
- Dedicated inventory workspace with KPIs, balance table, low-stock emphasis and receive/consume forms.

### UI-9 — Financeiro
- Dedicated finance workspace with income/expense/result/margin summary, ledger table and structured income/expense forms.

### UI-10 — Relatórios
- Dedicated reports workspace with report catalog, structured CSV/PDF/issue/export actions and issued-document history.

### Auxiliary screens included by UI-5
- Inputs: dedicated catalog-like table/form.
- Harvest: dedicated harvest table/form.
- Settings: structured preferences, backup/restore, import, feature flags and agricultural catalog controls.

## Architecture
The backend remains the source of truth for business rules and action semantics. The frontend owns presentation only through local UI contracts and screen components. `screen.kind` selects dedicated workspaces through the Product Runtime; no business rule is duplicated in React.

## Non-goals
- No persistence schema change.
- No mandatory external service or paid dependency.
- No fake weather, IoT or geospatial data.
- No redesign of P0/P1/P2 command semantics.
- Full mobile operational redesign remains UI-13.

## Acceptance criteria
1. No text `JSON de entrada` exists in the product UI.
2. No screen depends on the generic technical action editor.
3. All ten navigation screens have specialized human-oriented rendering.
4. Every existing user action remains reachable from the UI through structured controls.
5. Destructive actions require confirmation.
6. Existing P0/P1/P2 tests remain green.
7. New unit tests cover UI contracts/view-models and new E2E tests execute human journeys without raw JSON.
8. Web build and Windows release certification remain green.
9. IoT tests remain green and IoT remains optional.
