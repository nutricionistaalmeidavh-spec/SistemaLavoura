# Sistema Lavoura IoT-ready Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** deixar o Sistema Lavoura preparado para receber telemetria IoT opcional por adapters, sem alterar o funcionamento normal offline, sem custo recorrente obrigatório e sem exigir software adicional na instalação padrão do cliente.

**Architecture:** o produto ganha um núcleo IoT neutro em `src/iot/`, persistido no mesmo SQLite e isolado dos protocolos concretos. Adapters transformam MQTT, Modbus, LoRaWAN ou simulação em `TelemetryReading`; somente depois da persistência os eventos derivados seguem para EventBus, alertas, dashboard e relatórios. Controle físico permanece desabilitado no primeiro ciclo.

**Tech Stack:** Node.js >=22, Electron 44, React 19, SQLite existente, testes `node:test`, Playwright para UI; módulos RepoUteis reutilizados somente quando mantiverem instalação única/local-first.

**Spec:** `docs/superpowers/specs/2026-09-19-iot-ready.md`

## Global Constraints

- Produto continua funcionando 100% sem IoT.
- Compra por valor único; nenhuma mensalidade ou cloud obrigatória.
- Nenhum Docker, Node-RED, Mosquitto, ChirpStack, Redis, PostgreSQL, VPS ou daemon externo obrigatório.
- Dependências npm eventualmente necessárias a adapters devem ser empacotadas no instalador; não podem virar instalação manual do cliente.
- MQTT, Modbus e LoRaWAN são adapters opcionais, nunca dependências do domínio agrícola.
- Primeira entrega real é read-only; `iot:command` existe no contrato, mas controle físico fica bloqueado por padrão.
- Persistência continua no banco local do produto.
- EventBus recebe somente fatos já persistidos.
- Branch `roadmap/iot-ready` não deve ser mergeada enquanto o desenvolvimento paralelo em `migration/standalone-phase-0-8` estiver em movimento.
- Antes de integração final, atualizar/rebasear contra a branch escolhida como nova base e executar a suíte completa.

## Review Focus

1. IoT desabilitado ou sem configuração: o Lavoura deve iniciar e operar normalmente.
2. Payload duplicado/repetido: não pode gerar duas leituras lógicas quando houver identificador/sequence idempotente.
3. Adapter desconectado ou travando: não pode derrubar UI, banco ou outros adapters.
4. Telemetria malformada, fora de unidade ou com timestamp inválido: deve ser rejeitada sem alterar estado válido anterior.
5. Restore/upgrade de banco legado sem tabelas IoT: deve migrar sem perda e sem tornar IoT requisito do banco antigo.

## Critérios de aceite final

- Instalação padrão continua sendo somente `ArtiSys-Lavoura-Setup-*.exe`.
- Sem hardware e sem rede, todas as 10 telas/17 ações existentes continuam funcionais.
- Nenhum serviço pago ou infraestrutura externa passa a ser requisito.
- Mock IoT demonstra dispositivo, vínculo a talhão, telemetria, alerta e histórico de ponta a ponta.
- MQTT/Modbus/LoRaWAN ficam desligados até configuração explícita.
- Modbus e demais comandos físicos permanecem read-only/disabled por padrão.
- Restore e compatibilidade com base anterior continuam aprovados.
- Release certification existente continua fail-closed.
