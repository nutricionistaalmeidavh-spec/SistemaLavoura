# UI Productization Phase 0–3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the first commercial Lavoura UI layer through design tokens, a lighter shell/navigation, a screen-kind product runtime, and a specialized dashboard without changing business rules.

**Architecture:** Keep `src/presentation.js` as the vertical contract. Add pure UI model helpers plus React shell/runtime/dashboard components under `web/`; the runtime chooses specialized components by `screen.kind` and falls back to the existing generic workspace for later phases. The browser and Electron continue to use the same backend RPC contract.

**Tech Stack:** React 19, Vite 7, existing Electron runtime, plain CSS design tokens, Node test runner, Playwright.

**Spec:** `docs/design/2026-09-19-ui-phase0-3.md`

## Global Constraints
- Preserve the existing ten screen IDs and all P0/P1/P2 actions.
- No mandatory paid services or new cloud dependency.
- Do not fabricate map, weather, IoT or machinery data.
- Keep Electron and PWA/browser paths compatible.
- New visual code must work without Tailwind or a new styling dependency.

## Review Focus
- Existing admin login/session must continue through the new runtime.
- Unknown `screen.kind` must render the generic fallback instead of a blank page.
- Empty dashboard data must render zero/empty states without throwing.
- Narrow layouts must keep navigation reachable.
- Existing backend action/load signatures must remain unchanged.
