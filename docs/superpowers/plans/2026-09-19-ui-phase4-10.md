# UI Phases 4–10 Productization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove every remaining developer-facing JSON flow and ship dedicated commercial workspaces for Talhões, Safras, Operações, Insumos, Colheita, Estoque, Financeiro, Relatórios and Configurações.

**Architecture:** Keep `presentation.js` and all backend action semantics unchanged. Extend the existing Product Runtime with local UI contracts, reusable form/dialog/table primitives and specialized components by `screen.kind`, so presentation evolves without duplicating domain rules.

**Tech Stack:** React, Vite, Electron, existing Product Runtime, Node test runner, Playwright.

**Spec:** `docs/design/2026-09-19-ui-phase4-10.md`

## Global Constraints
- Preserve all current screen IDs and backend action names.
- No mandatory paid or external dependency.
- Local-first behavior must remain intact.
- IoT remains optional and must not regress.
- No raw JSON input in any end-user screen.
- Existing P0/P1/P2 functional QA must remain green.

## Review Focus
- Empty data sets must render useful empty states rather than broken tables.
- Invalid numeric/date values must be rejected or normalized before backend action calls.
- Destructive actions must require explicit confirmation and remain cancellable.
- Versioned records must preserve IDs/expected versions when edited or deleted.
- Missing optional backend data must not crash specialized workspaces.
